# 📸 Wedding Photographer Portfolio — Maria Kovalenko Photography

Односторінковий адаптивний лендинг-портфоліо для весільного фотографа, створений у рамках командного проєкту. Сайт інтегрується з динамічним API для завантаження галереї та відгуків, реалізований за методологією **Mobile-First** та сфокусований на максимальній продуктивності й бездоганному UX.

👉 **[Жива сторінка проєкту (Live Page)](https://valeriiovdiienko.github.io/team-project-2-wedding-photographer/)**

---

## 🚀 Основний та додатковий функціонал

* **Фіксований мобільний Header (Додатковий функціонал):** Для користувачів smartphones реалізовано закріплений (`position: fixed`) заголовок сайту. Це забезпечує постійний швидкий доступ до навігаційного меню в один клік без необхідності скролити сторінку вгору, що суттєво покращує мобільний UX.
* **Динамічна галерея (Portfolio):** Автоматичне завантаження весільних фото та категорій з REST API за допомогою бібліотеки `axios`.
* **Фільтрація та пагінація:** Сортування портфоліо за категоріями та підвантаження нових фотографій за допомогою кнопки *«Show More»*.
* **Динамічні відгуки (Feedbacks):** Дані про відгуки клієнтів завантажуються динамічно з сервера. Інтерфейс оснащено повноцінним, функціональним та інтерактивним слайдером на базі `swiper` із плавною анімацією. Реалізовано зручну навігацію: прогортання за допомогою кнопок-стрілок, а також повна підтримка свайпів на мобільних пристроях.
* **Валідна контактна форма:** Інтерактивна форма для запису на фотосесію з клієнтською валідацією обов'язкових полів та обробкою станів відправки за допомогою `izitoast`.
* **Асинхронний лоадер:** Індикація стану завантаження (`loader`) під час очікування відповідей від сервера для уникнення ефекту «порожнього екрана».

## 📐 Архітектурні підходи та методологія

### 📱 Повноцінний Mobile-First підхід
Весь проєкт спроєктовано та зверстано за принципом **Mobile-First**. Розробка починалася з найменших екранів мобільних пристроїв, а розширення для планшетів та десктопів додавалися поступово за допомогою прогресивного покращення. Це гарантує ідеальне відображення сайту на будь-яких смартфонах і суттєво економить ресурси пристрою під час первинного рендерингу.

### 🧩 Організація CSS та принцип DRY (Don't Repeat Yourself)
У проєкті створено **єдиний глобальний файл загальних стилів**, який виступає ядром усієї візуальної системи сайту. У ньому централізовано зафіксовані:
* Глобальна **типографіка** та мікросітка.
* Уніфіковані параметри **плавних анімацій та переходів** (`transition`).
* Базові стилі для **кнопок, інтерактивних елементів та ховер-ефектів**.
* Усі CSS-змінні для підтримки дизайн-системи макета.

**Що це дало команді:**
1. **Підвищення перформансу розробників:** Кожен учасник команди миттєво перевикористовував готові класи, не витрачаючи час на написання стилів з нуля.
2. **Чистота коду:** Повністю ліквідовано дублювання CSS-правил між різними секціями.
3. **Мінімізація помилок:** Стандартизація стилів звела до нуля ймовірність «розходження» візуалу між різними блоками лендингу.

## ⚡️ Оптимізація та продуктивність (Performance)

Десктопна версія сайту досягла блискучого результату в **98 балів** за метрикою продуктивності у **Google PageSpeed Insights**. Мобільна версія також була виведена з червоної зони завдяки наступним рішенням:

### 1. Оптимізація першого екрана (Hero Section & LCP)
* **Адаптивний Preload:** У тег `<head>` додано сучасний механізм попереднього завантаження картинок за допомогою атрибутів `imageSrcset` та `imageSizes`. Браузер смартфона починає завантажувати фон миттєво, не чекаючи парсингу та читання файлу CSS.
  
### 2. Оптимізація галереї та відгуків з API
* **Lazy Loading:** Для динамічних картинок активовано відкладене завантаження (`loading="lazy"`). Браузер качає лише видимі фотографії, суттєво заощаджуючи мобільний трафік користувача.
* **Асинхронне декодування:** До тегів `<img>` додано атрибут `decoding="async"`, який прибирає мікрофризи інтерфейсу під час скролу та рендерингу важких фото.

### 3. Оптимізація ресурсів
* **Очищення шрифтів:** З підключення Google Fonts вилучено невикористовувані стилі, що зменшило вагу шрифтів. Додано обов'язковий параметр `&display=swap`.

## 📂 Структура проєкту та деплой

Цей проєкт створено за допомогою **Vite**. Усі вихідні файли проходять автоматичну оптимізацію та мініфікацію коду перед публікацією в мережу.

### 🏠 Файли і папки

* **Розмітка (`src/partials/`):** Файли окремих компонентів сторінки (хедер, футер, секції) створюються в цій папці та динамічно імпортуються до головного файлу `index.html`.
* **Стилі (`src/css/`):** Усі файли стилів зберігаються тут та підключаються безпосередньо до HTML-файлів сторінок (наприклад, `index.css` для `index.html`).
* **Зображення (`src/img/`):** Локальні графічні ресурси додаються до цієї папки. Збірник автоматично оптимізує їх під час створення продакшн-версії. Оптимізація відбувається в хмарі (GitHub Actions), що повністю знімає навантаження з вашого комп'ютера та економить час розробки на слабких машинах.

### 🚀 Автоматичний деплой (CI/CD)

Публікація живої сторінки на **GitHub Pages** повністю автоматизована за допомогою GitHub Actions:

1. **Тригер:** При кожному `git push` у головну гілку проєкту (`main` / `master`) файли репозиторію автоматично копіюються на віддалений сервер.
2. **Перевірка та Збірка:** На сервері проєкт ініціалізується, проходить лінтинг (перевірку коду на помилки) та фінальну збірку командою `npm run build`.
3. **Реліз:** Якщо всі кроки пройшли успішно, готова мініфікована продакшн-версія файлів сторінки з папки `dist` автоматично відправляється в службову гілку `gh-pages` і оновлюється в мережі. У разі виникнення помилок збірки — детальна причина відобразиться в лозі виконання скрипта у вкладці *Actions*.

## 🛠 Технологічний стек

* **Складальник проєкту:** Vite

* **Стилі та розмітка:** HTML5, CSS3

## 💻 Інструкція для локального запуску

1. **Клонувати репозиторій:**
   ```bash
   git clone https://github.com
   ```
2. **Перейти в папку проєкту:**
   ```bash
   cd team-project-2-wedding-photographer
   ```
3. **Встановити залежності:**
   ```bash
   npm install
   ```
4. **Запустити локальний сервер розробки:**
   ```bash
   npm run dev
   ```
   *Сайт відкриється у браузері за адресою `http://localhost:5173/`.*

5. **Створити оптимізовану збірку коду (локально):**
   ```bash
   npm run build
   ```
   *Для знайомства та налаштування додаткових можливостей збірки звернись до [документації Vite](https://vitejs.dev).*
